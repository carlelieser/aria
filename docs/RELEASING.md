# Releasing

How to cut an Aria release.

> **The GitHub Actions release workflow is currently unusable.** Its `build-ios`
> job runs on `macos-latest`, and there is no macOS runner in the pool. Pushing
> a `v*` tag triggers the workflow, `build-ios` queues indefinitely, and the
> `create-release` job (which depends on it) never runs — leaving a stuck run and
> no published release. **Build locally and publish with `gh` instead** (below).

---

## Versioning

App version numbers come from `app.json` — `eas.json` sets
`cli.appVersionSource: "local"`, so EAS reads the version from the config, not
from a remote counter or from `android/app/build.gradle`.

Bump all three fields in `app.json` for every release:

| Field                      | Example                                 |
| -------------------------- | --------------------------------------- |
| `expo.version`             | `0.8.1-beta`                            |
| `expo.android.versionCode` | `2` (integer, monotonically increasing) |
| `expo.ios.buildNumber`     | `"2"` (string)                          |

Then align `package.json`:

```bash
npm version <version> --no-git-tag-version --allow-same-version
npx prettier --write app.json package.json
```

> Do **not** hand-edit `versionCode`/`versionName` in `android/app/build.gradle`.
> That directory is regenerated by `expo prebuild` from `app.json`; manual edits
> are overwritten.

## Building the artifacts

Builds run **locally** with the `preview` profile — never on EAS servers.

`eas build --local` still contacts Expo for credentials, so authenticate first:

```bash
eas login          # interactive; or set EXPO_TOKEN in the environment
```

The EAS project is `@devplex/aria`. Confirm with `eas project:info` if unsure —
`eas whoami` lists every account you can access, not necessarily the project's
owner.

Build both platforms:

```bash
eas build --platform android --profile preview --local --output out/aria-<version>.apk
eas build --platform ios     --profile preview --local --output out/aria-<version>.ipa
```

iOS signing uses local credentials from `credentials.json` (gitignored), which
points at `ios/certs/dist-cert.p12` and `ios/certs/profile.mobileprovision`. The
`preview` profile sets `credentialsSource: "local"`.

> **`expo-doctor` failures during the build are non-fatal.** EAS runs
> `expo-doctor` internally; it currently fails on out-of-date Expo SDK packages
> and logs `Error: npx -y expo-doctor exited with non-zero code: 1`, then
> continues. Do not mistake that line for a build failure — the build succeeds
> when you see `Build successful` / `You can find the build artifacts in …`.

Verify the artifacts before publishing:

```bash
# Android
"$ANDROID_HOME"/build-tools/*/aapt2 dump badging out/aria-<version>.apk | grep versionCode
# iOS
unzip -q out/aria-<version>.ipa -d /tmp/ipa && \
  plutil -p /tmp/ipa/Payload/*.app/Info.plist | grep -E 'CFBundleShortVersion|CFBundleVersion'
```

## Publishing the release

Add the F-Droid changelog for the new `versionCode`:

```
fastlane/metadata/android/en-US/changelogs/<versionCode>.txt
```

Create the GitHub release with both artifacts attached:

```bash
gh release create v<version> \
  out/aria-<version>.apk \
  out/aria-<version>.ipa \
  --title "v<version> (BETA)" \
  --notes-file <release-notes.md> \
  --prerelease \
  --target main
```

`gh release create` creates and pushes the `v<version>` tag, which **triggers the
broken release workflow**. Cancel the run so it doesn't sit stuck:

```bash
gh run list --workflow release.yml --limit 1 --json databaseId --jq '.[0].databaseId'
gh run cancel <id>
```

## Checklist

- [ ] `app.json` version, `android.versionCode`, `ios.buildNumber` bumped
- [ ] `package.json` version aligned; both formatted with Prettier
- [ ] Version bump committed and pushed to `main`
- [ ] F-Droid changelog added at `changelogs/<versionCode>.txt`
- [ ] APK and IPA built locally and version-verified
- [ ] `gh release create … --prerelease --target main` with both assets
- [ ] Triggered release-workflow run cancelled

## Known issues / follow-ups

These make the manual flow above necessary. Fixing either would simplify releases:

- **TODO: the release workflow can't run.** `.github/workflows/release.yml`'s
  `build-ios` job targets `macos-latest`, but there is no macOS runner in the
  pool (the only one was removed). Until it is re-pointed at an available runner
  — or the workflow is reworked to build Android on the self-hosted runner and
  skip/decouple iOS — a `v*` tag push only produces a stuck run. Releasing by
  tag alone is not possible; use the local flow above.
- **TODO: Expo SDK dependencies are out of date.** `expo-doctor` /
  `expo install --check` flag ~14 packages, which keeps the CI Expo Doctor and
  Expo Dependency Check jobs red on `main` and makes EAS log a (non-fatal)
  `expo-doctor` error during local builds. Some are downgrades EAS "expects"
  that the project intentionally moved past (e.g. `@shopify/flash-list`,
  `react-native-pager-view`, `react-native-worklets`), so the real fix is likely
  a mix of `expo install --check --fix` and adding deliberate overrides to
  `expo.install.exclude` in `package.json` — needs a device re-test, so it
  belongs in its own PR.
